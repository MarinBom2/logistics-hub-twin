# 프로젝트 목적: 커리어 방향 정리

## 1. 현재 나

- 경력 5년차 SW 개발자
- 주력: Java, Spring Boot / 배포 환경: AWS / 프론트: React
- DB·캐시: MySQL, Redis
- LLM 활용 경험: AWS Bedrock 기반 슬랙봇, AIOps 모니터링 설계
- 물류 허브 현장 경험 있음

## 2. 도메인을 바꾸려는 이유

- 일반 웹(커머스, 스타트업 서비스)은 AI로 빠르게 대체될 가능성이 높다고 판단
- WMS·물류·제조처럼 **현장 설비와 데이터가 얽힌 도메인**은 진입장벽이 높아 AI 대체가 늦고, 경력이 쌓일수록 대체하기 어려워짐
- 단, PLC나 설비를 직접 다루는 현장 엔지니어가 아니라 **설비 데이터 위에서 일하는 SW 개발자**로 간다
  - 지방 공장 출장이나 운전 부담이 큰 하위 레벨은 피함

## 3. 산업 자동화 계층과 목표 위치

```
[상위] 클라우드 / 데이터 / AI (Spring Boot, React, AWS, LLM)   ← 목표
[중간] MES·WMS·WCS / 설비 데이터 수집 서버 (Java, C#)          ← 목표
[하위] PLC / 공유압 / 현장 기계 제어                            ← 가지 않음
```

## 4. 목표 직무

| 직무 | 하는 일 | 내 강점과의 연결 |
|---|---|---|
| MES / WCS / WMS 개발 | 생산·물류 실적 집계, 모니터링, 설비 지시 | Spring Boot, React, MySQL이 그대로 쓰임 |
| 제조·물류 클라우드 / DX | 설비 데이터를 클라우드에 쌓고, LLM으로 분석·질의 | AWS 운영 + Bedrock·AIOps 경험의 연장선 |

## 5. 목표 회사군

- **제조 IT**: 삼성SDS, 포스코DX, 현대오토에버, 신세계I&C 등의 제조·스마트팩토리 사업부
- **스마트팩토리 솔루션 기업**: 엠아이큐브솔루션, 미라콤아이앤씨, 티라유텍 등
- **물류 IT·자동화** (지금 프로젝트와 직결)
  - 대기업 IT 자회사의 물류 사업부: LG CNS, CJ올리브네트웍스, 삼성SDS 등
  - 물류 자동화 설비 기업: 현대무벡스 등
  - 자체 풀필먼트를 운영하는 이커머스·물류 기업의 센터 시스템 조직

## 6. 현실적으로 알고 가야 할 점

- **근무지**: SI 방식으로 MES를 구축하는 회사는 프로젝트 기간 동안 고객 공장에 상주하는 경우가 많음
  - 지방 산업단지에 몇 달씩 머무를 수 있고, 오픈 시점에는 야간·주말 대응이 생김
  - 숙소나 셔틀이 보통 지원돼서 직접 운전하는 경우는 드묾
- **사무실 근무 비중이 높은 곳**: 제조사 인하우스 IT 조직, 솔루션·플랫폼 제품 개발, 클라우드 DX 조직
- **면접에서 꼭 물어볼 것**: "구축 프로젝트 현장 상주가 있나요?", "주 근무지는 어디인가요?"
- **연봉·안정성**: 회사마다 차이가 큼. SI 쪽은 제조사의 설비 투자 경기에 따라 프로젝트 수가 출렁임

## 7. 이 프로젝트(logistics-hub-twin)가 보여줄 것

두 축으로 위 두 직무를 모두 커버한다.

1. **설비 수집 → 관제** (MES / WCS 직무용)
   - 가상 PLC(Eclipse Milo, OPC UA) → MQTT → Spring Boot → 3D 관제 화면
2. **이벤트 데이터 + LLM 분석** (DX 직무용)
   - MySQL에 쌓인 설비 이벤트 이력을 근거로 자연어 질문에 답하는 기능
   - 예: "어제 용인 3센터 B 분류구가 왜 자주 막혔어?" → 적체 시간대, 집게차 대기, 유입량을 근거로 답변
   - 앞서 설계한 `LlmClient` 인터페이스 구조를 재사용
